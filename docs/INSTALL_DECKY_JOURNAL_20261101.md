# OXP3 staged journal coverage and integration fixture storage

The 2026-11-01 local-test full integration run reached staged verification without an out-of-memory kill, then stopped because the Decky report declared `var/lib/oxp3-installer/decky/runtime/settings/loader.json` while its installed `decky-order` journal was not included in coverage. The failed-image audit found this was the only uncovered path among 2,066 declared paths. This change includes that protected journal. For that exact path only, an installed `decky-order-light` journal must follow `decky-order`, and its original snapshot must match the predecessor's applied bytes and effective metadata. Both journal hashes remain in the proof; only the final applied state is compared to the live file. Other overlaps remain errors.

The integration check suites also exhausted Alpine temporary storage when exercising retained maintenance payloads. Their disposable scratch disks now back `TMPDIR` after QEMU vendor, exact scratch serial, writable state and minimum size checks; the delta fixture receives the same 4 GiB disk size. The scripts unmount the fixture on exit. The actual packaged delta suite also reached its five-minute deadline while running the maintenance interoperability case (315.6 seconds including host setup and cleanup); it now uses the same twenty-minute task deadline as the integration suite. This changes test storage and the measured insufficient test deadline, not target installation or recovery behavior.

Source tests and the Windows build are separate gates from packaged guest integration and physical hardware acceptance. The candidate model builder identity is `0.1.0-localtest.20261101.12`; rebuilding and validating both runtime copies, a fresh 2 GiB end-to-end VM installation, packaged integration and maintenance checks, upgrade/recovery, and hardware acceptance remain required before release. This record does not claim those gates have passed.

The full Windows Python run found two errors in the synthetic runtime-consumer fixture: it copied the parser lock but omitted its source-whitelisted vendor members. The actual public source export and package contained those locked members. The test fixture now copies the whitelisted vendor tree too; all eight tests in that module pass. A full-suite rerun remains a separate gate for the next frozen source candidate. No vendor source or runtime policy was changed.

The full selected 2 GiB TCG installation subsequently completed slot A's model apply and strict verification after approximately fifteen minutes of the integration guest. The shared twenty-minute integration deadline leaves insufficient allowance for configuring and verifying slot B. Image integration now has a forty-minute deadline; guest RAM, per-hook deadlines, cancellation and verification remain unchanged. The two isolated integration test tasks retain their twenty-minute deadlines. A fresh final-package full A/B run is required to validate this scheduling change.
