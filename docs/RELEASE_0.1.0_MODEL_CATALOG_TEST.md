# 0.1.0-preview — 机型清单与 OXP3 本地实机测试包

日期：2026-10-29。用户要求制作完整本地包，优先测试 OXP3；本轮不公开安装包、Tag 或 Release。

安装器读取 `FlightDan/Boiler-devices` 的固定提交
`d72035c81126b5149d70723a104b631835a4d037`，对目录和两份机型 manifest
核对大小与 SHA-256。网络不可用时使用同一版本的随包快照。此入口显示 OXP3 和
X2 Mini 的推荐、条件适用、可选、排除与待实现项目；指南本身不能授权执行脚本。

OXP3 随包提供 `0.1.0-localtest.20261029.3` 开发候选，只有用户明确点击
“使用随包测试适配（仅本次信任）”后才校验并选择。安装勾选从能力白名单传入
受保护安装方案，再进入现有受管理 Linux guest；包内文件及 `selection.json`
不被改写。依赖先规范化排序，有效选择保存在原私有日志中用于重试与复验。
既有冻结包、签名目录和本地导入的信任规则保留。

默认五项为 input、multifunction、gyro、xe-dsb、split-lock；使用旧适配策略需要
明确接受暂停 SteamOS 系统镜像更新。GM7 因桥接入口没有已复核目标 SSD 上下文，
在本候选中明确禁用。X2 Mini 本轮只提供指南，没有可执行随包组件；PL4 175W
仍待实现，不提供可勾选的虚假安装项。

OXP3 原始资源只取自已经公开并固定 SHA-256 的完整 1.0.6 安装包；本次重建
没有读取工作区内研究目录。候选保留 SteamOS 3.10 / BUILD_ID 20260924.1000 /
内核 `7.2.4-valve1-1-neptune-72-g5ab4af5e2eb9` 等现有条件。

完整解压包的临时盘检查发现 Windows 深层资源路径超过传统 MAX_PATH 后被误报为缺失。
导入与完整清单验证现在仅在 Windows 文件 I/O 内部使用扩展路径；逻辑相对路径、
显示目录、签名/哈希及链接拒绝规则不变，不要求用户修改系统长路径注册表设置。
进一步对真实只读 FAT 导出逐项比对，确认 Windows QEMU vvfat 会静默遗漏达到
260 字符的路径。主机传输现在按需复制到工作区中的短独立目录，并在启动 QEMU
前校验所有物理文件路径；仍超限时明确要求选择更短工作目录，不忽略库存错误。
