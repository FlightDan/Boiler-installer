# Boiler 0.1.0-preview — Decky 与 OXP3 上游修复，2026-10-30

本次交付为本地测试候选；安装器显示版本保持 0.1.0-preview，OXP3 模型使用新的 `0.1.0-localtest.20261030.7`，保留维护器为 `0.1.0+maintenance.10`。不覆盖既有公开资产，也不以本地构建声明公开发布或实机验收完成。完整源码提交、ZIP 大小、SHA-256、逐文件库存和最终检查结果由本次 `dist/upstream-repairs-20261030-final2/verification.json`、`dist/upstream-repairs-delivery-20261030/result.json` 记录。

- 通用及 OXP3 自带的 Decky 均更新为官方 3.3.1，包含对应源码归档和 GPL 许可；沿用原有互斥、依赖和部署事务。新装写入的版本标记与维护器写入的版本标记一致。
- OXP3 输入模板补入 `HID 1a86:fe02` 底座键盘接口，使 Console/Keyboard 组合进入现有 InputPlumber 输入路径。input 和 gyro 模板均处理；启动 helper 同样在 `/run` 的生成副本补入接口，已有 `/etc` 模板和陀螺仪校准不被改写。该改动不宣称额外实现底座 Home/G 键，也不替换 InputPlumber 二进制。
- 新增独立 `oxp3:speaker-route` 静态组件。启动会话和恢复后，确认 OXP3、ALC245 与耳机孔为空才处理误选的耳机配置；当前 WirePlumber 近期明确报告 Speaker UCM 初始化失败时才重选原扬声器配置。正常路由不重选；写入失败明确报告，并尽力恢复原配置。用户服务以 Type=exec 启动，不等待检查结束才完成会话 target；恢复服务采用 systemd sleep.target 的退出钩子。
- xevmafix 仅为当前精确 SteamOS 3.10 / `7.2.4-valve1-1-neptune-72-g5ab4af5e2eb9` 构建。它是大规模 GPU VMA 重绑定分配失败的临时缓解，不代表 Valve 后续内核最终方案。模块、内核头文件、编译工具链、上游源码和官方 xe 二进制均有独立来源记录；保留机器码匹配检查和运行时系统/内核门槛。模块不能在线卸载，恢复文件后需重启才能撤销已加载的修复。

OXP3 仍受原模型的精确系统/内核限制；不扩展旧模型到其他内核。X2 Mini 保持原 `localtest.20261030.2` 字节与 manifest 锚点。保留原 Opti2XMX、三个 OptiScaler 原档、Battery 0.2.2 和麦克风。CPU 五份生产源码逐一匹配公开 `72f864e0498c10366493c74608c5ffed62cc99ca` 基线；未导入私有研究。HDR 源码和载荷逐文件保持不变。

## 安装、维护与恢复

新装与机型包导入沿用现有组件选择入口；底座修复随原 input/gyro 所有者部署。speaker 与 xevmafix 使用独立静态组件和原 Engine 的备份、校验、恢复；维护菜单中的“机型附加修复”显示这些选项。每个组件各自提交，不声称多组件整体原子。Windows 与保留维护器携带相同的两个完整机型包，分别核对全部文件大小、SHA-256 和 manifest。

安装过程不执行真实待机、休眠、重启或加载内核模块；新增服务在后续相应启动阶段激活。恢复使用原始快照并拒绝覆盖外部修改。已加载内核模块与服务的运行效果需按重启要求撤销，文件校验不替代运行效果验证。
