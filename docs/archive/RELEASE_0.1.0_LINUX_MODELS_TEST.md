# 0.1.0-preview — Linux 机型维护同步测试包

日期：2026-10-29。本轮只生成供 OXP3 实机测试的完整本地 ZIP，不推送源码、Tag 或 Release。

Linux 通用维护器与 Windows 安装器读取同一份 `FlightDan/Boiler-devices`
固定提交 `d72035c81126b5149d70723a104b631835a4d037`，继续校验大小和 SHA-256，
断网使用同一离线快照。机型指南不能授权执行。两端适配 ID、默认项、依赖和名称
来自已校验的机型包，选项白名单与依赖检查共用 `protocol/model_options.py`。

Linux 新增 KDE 应用菜单入口“Boiler 维护工具”，包含机型指南、逐项选择、计划审阅、
安装/接管、验证和恢复。窗口由桌面用户运行，仅固定后端通过 PolicyKit 授权。
本地开发包须明确本次信任；安装还须确认保留已有系统镜像更新暂停策略。
界面使用目标真实槽标签与 PARTUUID，显示共享目录影响范围、依赖和不可用原因。

维护运行时修订为 `0.1.0+maintenance.3`；OXP3 机型包为
`0.1.0-localtest.20261029.5`。Windows 新装默认仍为 input、multifunction、gyro、
xe-dsb、split-lock 五项。Linux 显示相同的 28 项来源能力，并额外显示指南中的待实现项；
具体可用性由真实系统版本、内核、软件包、共享槽兼容性、文件所有权及现有更新暂停
策略决定。Linux 通用文件维护不修改 EFI，因此 rEFInd、GM7、split-lock 明确不可选；
Waydroid 需要独立的宿主包与 Android 生命周期，也明确不可选。Windows 已安装的
split-lock 启动设置保持原样，Linux 不声称管理它。Linux 支持的默认组合为前四项。

OXP3 维护通过新声明的 `boiler-model-maintenance-v1` 入口复用原公开固定资源的
文件计划与事务 Store，使用独立 Boiler 私有状态和启动保护。安装虚拟机专用入口及
其保护不被放宽，也不伪造虚拟机标记。计划绑定目标、已安装状态、选项、机型包哈希
和实际文件；执行时在现有 Engine 锁及 SteamOS 根目录保护窗口内再次核对。
完整校验后的机型包被保留在私有状态中，验证与恢复不依赖安装器原缓存。

首次接管安装器适配时核对并保存真实原始文件，不修改原安装日志、原维护器公钥或身份。
恢复后可重新安装；中断操作保留前后快照和回执，外部修改不能被当作安全恢复状态。
当前版本更改已纳管组合须先明确恢复该组合，再选择新组合安装，不把多步更改宣称为
原子操作。接管后应使用 Boiler 管理同一组适配，避免再用旧维护器修改同一批文件。
其他槽上的旧维护器如仍拥有拟修改的共享文件，本次维护会拒绝产生重复所有权。
