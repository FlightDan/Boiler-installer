# ONEXPLAYER 模型微码接入与实机验收 · 2026-11-19

OXP3 和 X2 Mini 的 TOON 都引用同一份 Intel Panther Lake 输入和许可证。品牌构建器从固定适配提交 `33333215e61862d062f972b7426f58c20b503006` 生成 `onexplayer:intel-microcode`，默认按 TOON 留空。两个机型映射复用同一归档成员。普通安装器对所选机型的每个槽分别生成早期 initramfs，CPU 适用性由启动时的内核匹配。

安装和维护共用 `microcode_boot.prepare`、早期归档校验和 Engine 二进制文件事务。事务保留原始启动字节及权限。实机维护还核对机型 DMI、每个逻辑 CPU 的 Intel 签名、平台掩码和运行版本。对已有安装单独补装时，维护器保留微码输入、许可证和绑定原清单，沿用原机型包与其他构件的归属。

本地品牌候选 `2026.11.19.4-localtest.microcode`，最终保留维护器 `0.2.0+maintenance.32`，引擎 `0.1.7`。品牌 ZIP 为 447,332,604 字节，SHA-256 `b5cfcefd1b358cc3959a51ba412c45399d9e6786046a2a35093846cb75897a24`。两台机型的包已重新导入并校验去重。Windows Release 构建及综合、离线目录、品牌插件组合自检通过，两机型均按 TOON 默认不选微码。

Windows 全量源码回归运行 1,123 项，发现一个旧 X2 Mini 可选升级元数据格式错误阻断原包恢复的回归，另有 100 项平台跳过。`.32` 修复了回退路径。修复后 Windows 定向 85 项（9 项跳过）和 Linux 定向 120 项（1 项跳过）均通过，Windows 也单独复验了原失败用例。全量套件待复跑。

Linux A/B 普通目录夹具使用重新导入的 OXP3 机型包和实机备份的原始 initramfs。两个槽都通过安装和正常维护校验，随后将原始 initramfs 字节与文件权限逐一还原。

这个品牌包是微码本地验证候选，安装端需要引擎 `0.1.7`。在本机做 Windows 安装准备时，工作目录须选 E: RAID。包里的 OXP3 指纹服务仍带有旧库路径故障，实机上的指纹库路径修复由此前的独立事务提供。

OXP3 实机 SteamOS 3.10 B 槽重启成功，`7.2.4-valve1-1-neptune-72-g5ab4af5e2eb9` 内核报告 `Updated early from: 0x0000011a` 和 `Current revision: 0x0000011d`，14 个逻辑 CPU 均返回 `0x11d`。维护器验证启动内容通过，正常恢复入口可审阅原事务。实机重启时使用 `.31`，随后升级到 `.32` 并再次通过原微码事务校验。系统根保护已恢复，EFI GRUB 配置与 AMD 微码镜像均与备份逐字节一致。

实机验收覆盖当前 OXP3 B 槽的补装、重启和校验。物理 A 槽、X2 Mini、正式签名和公开下载留待单独验收。本地归档、启动备份和回执登记于 RAID 适配保留区的统一清单。
