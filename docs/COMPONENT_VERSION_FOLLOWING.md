# 机型构件版本解析与维护

机型在权威适配仓库的 TOON 中申请资源 ID。省略版本表示跟随最新兼容稳定版。可选的 `version` 固定该机型使用的稳定版，`default: false` 保留默认不勾选的选择。现有机型可直接使用按 ID 声明的申请。

```toon
resources[2]:
  - id: "resource:onexplayer-microphone"
  - id: "resource:oxp3-speaker-route"
    version: 2.1.0
    default: false
```

示例中的版本仅说明字段格式。变更机型申请、默认值和锁定版本时，在 `FlightDan/Boiler-adaptations` 提交源记录并重新生成安装器的锁定快照。

## 发布构件与生成机型包

1. 构件发布包沿用 `DevicePackage`，包 ID 和版本与包内唯一的 `ComponentManifest` 一致。`component_release` 记录 TOON 资源 ID 和 `stable` 或 `preview` 通道。包声明精确的权威适配提交、支持的机型与系统。依赖、冲突和最低维护引擎版本随已校验的载荷进入索引条目。构件发布至少要求引擎 0.1.6，旧安装器会跳过这类索引条目。使用 `scripts/resolve-model-components.py component` 验证打包输入，生成并重导入 ZIP，输出待签名索引条目。
2. 生成机型包前，用 `affected` 子命令从指定提交找出申请该构件版本的机型。对相应环境运行 `model` 子命令，输入已签名设备索引缓存、实际目标环境 JSON、已认证的基础安装机型包、权威 TOON 快照提交和新的机型包构建版本。环境字段为 `architecture`、`os_id`、`os_version`、`device_id` 和 `kernels`。本地预下载目录可按签名条目的 manifest SHA-256 命名，读取时仍验证签名锚、文件清单及实际字节。
3. 对有相应 TOON 申请的构件，选择符合机型、操作系统、内核和依赖条件的稳定版本。生成的机型包记录具体构件版本、源提交、清单 SHA-256 和索引 SHA-256。现有受锁的基础机型文件仍随原契约提供。新的独立构件使用自身资源 ID，已有静态构件保留原运行时身份及目标文件集合。
4. 为每种支持的系统环境生成机型版本。Windows 列表展示这些版本的系统与内核兼容信息，安装阶段用实际镜像再次验证。当前 WPF 流程在读取最终系统镜像前选择机型包，多个系统环境的候选由用户在机型页选择。每个环境的候选包内部已经解析到该环境的兼容版本。安装确认绑定已选机型包清单，离线包使用生成时锁定的载荷。
5. 构件、机型版本和索引由项目现有签名发布流程发布。已有附件和机型包版本保持不可变。为支持降级，当前签名索引保留允许使用的历史版本及撤销记录。

## 维护与恢复

维护器在「检查更新」中列出当前根文件系统已安装的兼容构件。普通更新使用最新兼容稳定版，执行前显示具体版本并要求确认。用户可以选择仍在签名索引内且适用的旧版。降级事务同时固定所选版本，更新检查继续显示固定状态。「恢复跟随稳定版」需要审阅当前可用的同版或更高版本。状态由构件事务持久化，恢复活动代次时一并恢复旧状态。

此通道覆盖现有 Engine 管理的静态文件构件。BE201 专用资源、脚本或固件专用处理器、共享 Home 和跨槽位资源继续走各自的维护与恢复流程。固定选项作用于当前根文件系统的组件所有权，另一个 A/B 槽位有自己的维护状态。

专用维护审阅和回执分别记录维护包版本和构件版本。共享构件的应用显示将写入的版本，验证与恢复读取实际已安装的代次。BE201 和跨槽位资源按槽位报告已安装与期望版本，恢复回执还记录存在的上一受管版本。脚本适配有受管构件记录时使用该记录的版本，早期安装记录仅在有依据时显示构件版本。旧审阅计划仍使用原有的审阅摘要、来源和目标状态约束。
