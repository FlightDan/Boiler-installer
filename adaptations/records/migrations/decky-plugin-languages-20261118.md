# Decky plugin languages

The Steam quick access menus for fan, CPU, battery, lighting, fingerprint unlock, Restart to Windows, and Opti2XMX support English, Simplified and Traditional Chinese, Japanese, Korean, German, French, and Spanish. The pinned Decky Loader 3.3.1 already contains the six locale catalogs and uses English for missing entries.

The plugins use Steam's display language. They handle Steam names, regional variants and Chinese script subtags. An unsupported language or missing message uses English. Existing component identifiers, RPC names, control behavior, and user configuration remain compatible.

The shared resolver lives in `common/plugin-i18n/decky-locale.mjs`. Run `python -B scripts/refresh-decky-locales.py --write` after editing it. The Restart to Windows frontend imports the resolver at build time. Build it in an isolated copy of `common/plugin-i18n/` with the original `package.json`, `pnpm-lock.yaml`, `rollup.config.js`, `tsconfig.json`, and `plugin.json` from `common/scripts/windows-reboot/` placed in `restart-windows/`. Run the frozen pnpm install, typecheck, and Rollup build there and copy back only the generated `dist/index.js`.

Run `python -B scripts/refresh-decky-locales.py --check` and `node --experimental-vm-modules --test common/plugin-i18n/locale.test.mjs` for the shared resolver, English fallback, and a render of each first-party plugin in every new language.

The fan source is based on `payload/legacy/integration/oxp3-fan/005.bin` from the retained OXP3 legacy payload. Its SHA-256 is `a585fb60b5fdb86af7840f56d6bcf4ef6694a9d89a78c01601582705f64ce746`. The other base frontends are bound by the original source inventories. The original frontends and signed upstream archives remain byte-for-byte reproducible.

Opti2XMX was rebuilt from `FlightDan/Opti2XMX` commit `ce85f88fef1304ad69fdd62046578bbf369a797c` at tree `32cb248d331483d62b6a1dfcde3e3ba2d2d3e4f8`. Overlay the files in `common/plugin-i18n/opti2xmx/source/` onto that exact upstream checkout. Install with the frozen upstream pnpm lock and run TypeScript, Rollup, and the upstream frontend test. Copy the built `dist/index.js` to `common/plugin-i18n/opti2xmx/index.js`. The Opti2XMX source license accompanies the frontend. The verified package override only applies to the installed UI member referenced by `integration/manifest.json`. The original Opti archive inventories, mirrors, and runtime describe the base inputs. The new package manifest records the override paths and canonical commit separately.

`scripts/build-localized-model.py` builds new OXP3 and X2 Mini local-test packages from explicitly supplied unsigned base packages and manifest digests. Set `BOILER_GIT_EXE` to the verified Git executable when Git is unavailable on PATH, and pass the exact canonical source commit. The builder verifies package and EFI closures, changes the UI bytes the existing install and maintenance routes consume, and advances affected component versions. Package inventory validation is a separate gate from installation, maintenance upgrade and recovery, and SteamOS hardware validation. Publication requires new signed production inputs and a separate release.
